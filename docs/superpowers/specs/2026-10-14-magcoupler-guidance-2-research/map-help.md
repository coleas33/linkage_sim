## 0. Headline findings

1. **Every one of the 87 empty-help inputs is a PORTED input** (none is `rust_only`). Their Python help is also `""`, and `tests/python_schema.rs:93-135` requires Rust label, unit, help, cell and choices to equal Python's exactly. **So filling any of the 87 helps in the engine metadata fails that test**, unless a new mechanism is added. All 11 Rust-only inputs already have help.
2. **Python oracle is declared uneditable**: `reference/README.md:5-9` ("Do not edit `magcoupling-py/magcoupling/`"), `docs/ai/03-structure.yaml:13` ("READ-ONLY, never edit; parity and differential tests compare against it unchanged"), `docs/ai/02-system.yaml:86`. Editing Python `param(...)` strings and regenerating `python_schema.json` would work mechanically but breaks that rule.
3. **Existing escape hatch is help-only and tied to approved corrections**: `Deviation.workbook_help` (`src/engine/deviations.rs:221-225`; read by `tests/common/mod.rs:189-198`, `tests/python_schema.rs:110-111`; checked by `tests/deviations.rs:2004-2031`). It has no path for labels. Precedent for filling an EMPTY help exists (workbook text `""`: `deviations.rs:288` E1, `:1296` E20 beta), but each entry belongs to an audit row.
4. **Help is hover-only** and appears in exactly two input places: the row tooltip (`input_ui.rs:114-117,140` via `inputs.rs:907-940`) and the two Size-tab sliders (`size_controls.rs:322`). With empty help the tooltip's first line is the raw path (e.g. `metal.runout_mm`). Help is NOT searched by the filter, NOT in any export, NOT in design files or share links.
5. **Labels are the widest-reaching lock**: 161 of 172 labels are Python-parity locked; 16 are also pinned by GUI/guidance test literals (section 3.4); 7 are suffix-colliding and get a heading appended by the slice-1 C-3 rule (`guidance.rs:857-891`); the filter test expects exactly 3 inputs to match "gearbox" (`inputs.rs:1478-1496`, `panel.rs:2485,2519`).
6. **Cleanest zero-lock route for help**: a GUI-side lookup consulted by the two display sites, leaving engine metadata and `python_schema.json` untouched (details and alternatives in section 4).

## 1. Where inputs are defined and how label, help, unit and group are stored

- **Metadata type**: `InputMeta { name, ty, unit, label, help, cell, choices, range, assumption, rust_only }` at `src/engine/meta.rs:130-151`. All strings are `&'static str`. Builders `param(unit, label, help, cell)` (`meta.rs:153-173`, Python's positional order) and `param_rust_only(unit, label, help)` (`meta.rs:175-195`, no cell); chained `.range()`, `.log()`, `.choices()`, `.assumption()` (`meta.rs:197-233`).
- **Declaration**: one `inputs!` block per struct, one line per field `name: type = default => param(...)` (macro `meta.rs:787-901`; the field's `FIELDS` const at `:824-831`). Declaring files: `model.rs:112` (`MagnetInputs`), `:154` (`CouplingInputs`); `metal_design.rs:21`; `calibration.rs:36`; `materials.rs:21,51,95,126,164`; `temperature.rs:49,74,182,193,215,271,293,313`; `clamps.rs:117`. The root `DesignInputs` composes groups at `api.rs:40-53`.
- **Group** is not stored on the field: it is the dotted path prefix (`coupling`, `coupling.magnets`, `metal`, `calibration`, `materials[.steel|.nickel|.screws|.parts]`, `temperature[.duty|.demag|.adhesive|.mismatch|.slip_loss|.thermal|.adhesive_life]`, `clamps`). The GUI maps prefix to heading with `SECTION_LABELS` (`gui/inputs.rs:41-60`) and arranges the same inputs a second way in `WORKFLOW` (`inputs.rs:117-582`: 8 groups, sections, `advanced` flag) plus `KEY_DESIGN` (`inputs.rs:27-38`). A test requires every input in exactly one workflow section (`inputs.rs:984-1040`).
- **Flat view**: `input_rows(&DesignInputs)` (`meta.rs:686-696`) yields `InputRow { path, meta, value }`; `InputCatalogue` (`inputs.rs:595-793`) wraps it as `InputEntry { path, meta: &'static InputMeta, default, haystack }`. `InputCatalogue::get()` is the single source the GUI reads labels and help from (slice-1 spec 4.1: "Fix labels come from InputCatalogue at display time (one source); guidance text never types a label", `docs/superpowers/specs/2026-10-13-magcoupler-guidance-design.md:119-120`).
- **Exported copies of the metadata**: `tests/data/input_schema.json` (Rust side; keys path, type, label, unit, help, cell, default, choices, range, assumption, rust_only; `tests/schema.rs:31-58`) and `tests/data/python_schema.json` (Python side; `reference/magcoupling-py/tools/gen_differential.py:220-236`). `gen_differential.py` reads only path/type/range/choices/default/rust_only from the Rust file (`gen_differential.py:251,271,408`), so a label/help-only change never alters differential data.
- **Defaults**: `input_schema.json` records the WORKBOOK default (`DesignInputs::defaults_with(Deviations::NONE)`, `schema.rs:32`), not the app default. They differ for 5 inputs; 3 of them are empty-help (`manual_inner_br_T`, `manual_outer_br_T`, `calibration.br_T`: app 1.30 T by E3, workbook 1.29 T). The table in section 5 shows the app default and notes the workbook one.

### 3.5 Slice-1 label machinery that a relabel must respect

- **C-3 disambiguation** `fix_label` (`guidance.rs:857-880`): a label that another input's label equals, or ends with as whole words (case-insensitive, `ends_with_label` `:882-889`), is followed by its group heading: `Raise Boss outside diameter (Shaft clamps)`. Today this fires for exactly 7 inputs: `coupling.c_end` (vs `calibration.c_end` "Original end-effect coefficient"), `coupling.mu0` / `calibration.mu0` (identical label), `materials.steel.modulus_GPa` (vs "NdFeB elastic modulus"), `materials.steel.density_g_cm3` ("Density" vs "Aluminium cap / adapter density", "Sleeve density"), `clamps.alloy` ("Aluminium" vs "Specific heat, aluminium", "Friction coefficient, nickel plate on aluminium"), `clamps.boss_od_mm` (vs "Shaft boss outside diameter"). Relabelling changes this set silently; the guard is `every_input_has_its_own_fix_text` (`guidance.rs:2467-2477`: no two inputs may give the same `Raise <label>` text).
- **`SIZE_TAB_ALIASES`** (`guidance.rs:154`): one entry, `coupling.inner_back_apothem_mm` -> `size_controls::DIAMETER` = `Outside diameter` (`size_controls.rs:26`); used by `fix_label` (`guidance.rs:858-863`), the panel (`panel.rs:38,597`) and pinned by `guidance.rs:2420-2427` ("Raise/Lower Outside diameter"). The input's own label stays `Inner magnet back apothem, including bondline` (Python-locked); the inverse-sizing picker calls the same input `Ring radius` (`gui/sizing.rs:84`), a third name; the geometry/dashboard call the result "Cup outer diameter"/"rotating OD" (audit UI-4).
- **Lint coverage**: `no_guide_text_carries_workbook_jargon` (`guidance.rs:3326-3330`) runs `plain_text_violations` over `every_text()` (`guidance.rs:2239-2275`), which includes `fix_text` of every fix input. So any label that appears in a fix must itself be free of `C\d{2,3}`, `E\d{1,2}`, `workbook`, `Addendum`, `Rust-only`, `Calculator!` (today's fix labels are).
- **Filter**: label text is part of the haystack, so a new label word changes filter hit counts (e.g. adding "gearbox" to any label breaks `3 of {total} inputs`).
- **Docs that quote labels**: `README.md:113` (E14 help), `:301`, `:306` quote label/help text; the memory rule "every code change must include doc updates" means README and `docs/ai/*.yaml` need the matching edit.
